# Grammar Cat 初期实现方案

## 技术选择

首版采用 **HTML、CSS 与原生 JavaScript**，不引入框架或后端依赖。这样可以先验证内容结构、练习流程与视觉方向，也能直接用任意静态服务器预览。页面稳定后，建议迁移到 TypeScript + React/Vite：组件会对应首页、知识点、练习、统计和 AI 答疑界面。

## 关键数据与练习流程

每道翻译题应保存中文题干、参考答案数组、答案单词数、考查语法标签、解析和常见错误。题面只显示中文、答案单词数和与单词数相同的空格，不显示英文关键词、首字母或参考答案。提交时先做大小写、标点和空白标准化，再进行参考答案匹配；无法精确匹配时展示参考答案、语法标签与针对性解析。每日题目从带标签的题库抽取 30 道，完成记录写入本地存储；有账号系统后再同步至服务端。

翻译测试的本地存储应至少包含 `currentQuestionIndex`、以题目 ID 为键的 `answers`，以及 `completedQuestionIds`。在用户每次输入、完成题目和切换题目时更新存储；刷新、进入语法精讲或返回测试时从该状态恢复。只有用户确认「重新开始测试」时才清空该状态。

## AI 答疑预留

前端只调用 `ai-service`，由它向未来的 `POST /api/ai/questions` 发送：当前知识点、学生问题、作答内容及可选的错题标签。服务端负责认证、限流、敏感信息处理和模型调用；不要让浏览器直接保存模型密钥。这样可在不改动课程和练习组件的情况下增加 AI 窗口。

## 下一步实施顺序

1. 确定首批语法目录与每个知识点的内容模板。
2. 建立 JSON 题库，并完成单题翻译输入、单词数提示和反馈页。
3. 加入 30 题日计划、正确率、错题本和学习天数的本地持久化。
4. 迁移至 TypeScript 组件架构，接入账户与后端同步。
5. 实现受保护的 AI 服务端接口和答疑窗口。
